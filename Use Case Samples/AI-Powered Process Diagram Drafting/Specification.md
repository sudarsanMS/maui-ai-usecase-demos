# Specification

## Overview
Create a sample application that converts a natural-language process description into an editable flowchart using Syncfusion .NET MAUI Diagram and an AI workflow extraction service. The AI must return structured JSON only. The application must validate the response before rendering and must preserve the current diagram if the response is invalid.

## Primary Control
- Syncfusion .NET MAUI Diagram is the primary rendering and editing control.
- The diagram must support user edits after generation.

## AI Capability
- The AI capability is limited to structured workflow extraction.
- The application must depend on an abstraction for workflow extraction and must not be tightly coupled to a specific AI provider.
- The AI response must be parsed into a workflow model and validated before any diagram update.

## Purpose
Convert natural-language process descriptions into editable flowcharts that users can review, refine, and accept.

## Target Users
- Business analysts
- Process owners
- Operations teams

## Application Scope
- Single screen
- Single AI workflow
- One input-to-diagram generation flow

## Included Scope
- Accept natural-language process descriptions
- Generate a basic flowchart draft
- Support Start, Process, Decision, and End nodes
- Generate connectors and decision branch labels
- Allow editing of generated diagrams
- Allow Accept Draft, Regenerate, and Discard actions

## Excluded Scope
- BPMN generation
- UML generation
- Swimlanes
- Process automation
- Workflow execution
- Workflow optimization
- Multi-user collaboration
- Automatic publishing
- Automatic saving
- External workflow integrations

## User Flow
1. User enters a process description.
2. User selects Generate Draft.
3. AI returns structured workflow JSON.
4. Application validates the response.
5. Diagram renders nodes and connectors.
6. User reviews and edits the result.
7. User selects Accept Draft, Regenerate, or Discard.

The application must never automatically publish, execute, or approve workflows.

## Screen Requirements

### Desktop Layout
Left panel:
- Process description input
- Example selector
- Generate button

Right panel:
- Diagram surface
- Review actions

### Mobile Layout
- Process description input
- Generate button
- Diagram surface
- Review actions

The input section must collapse after generation to maximize diagram area.

## Required UI Elements
- Page title
- Multiline text input
- Example process selector
- Generate Draft button
- Diagram canvas
- AI warning banner
- Accept Draft button
- Regenerate button
- Discard button

## Diagram Mapping Rules
- Start → Terminator
- Process → Rectangle
- Decision → Diamond
- End → Terminator
- Flow → Directional Connector
- Decision Branch → Connector with label

Additional rules:
- Top-to-bottom layout
- Orthogonal connectors
- Node positioning generated by application logic
- AI must not return diagram coordinates

## AI Responsibilities

### AI Must
- Extract only workflow content described by the user
- Identify steps, decisions, outcomes, and branches
- Generate concise labels
- Return valid JSON
- Return warnings for ambiguities

### AI Must Not
- Add workflow steps not described by the user
- Make business decisions
- Generate node coordinates
- Execute workflows
- Replace edited diagrams without confirmation

## AI Response Contract

Support the following JSON schema:
```json
{
  "title": "string",
  "nodes": [
    {
      "id": "string",
      "type": "start|process|decision|end",
      "label": "string"
    }
  ],
  "connectors": [
    {
      "id": "string",
      "sourceId": "string",
      "targetId": "string",
      "label": "string"
    }
  ],
  "warnings": [
    "string"
  ]
}
```

Supported node types:
- start
- process
- decision
- end

## Validation Rules
Validate before rendering.

Rules:
- Node IDs must be unique.
- Connector IDs must be unique.
- Connector source and target nodes must exist.
- Exactly one start node must exist.
- At least one end node must exist.
- Node type must be supported.
- Node label cannot be empty.
- Self-referencing connectors are invalid.
- Invalid responses must not modify the current diagram.

## Limits
- Description length: 1500 characters
- Nodes: 20
- Decisions: 6
- Connectors: 30
- Node label: 60 characters
- Connector label: 30 characters

## Editing Requirements
Users must be able to:
- Move nodes
- Edit node labels
- Add nodes
- Delete nodes
- Reconnect nodes
- Modify connector labels
- Undo changes
- Redo changes
- Fit diagram to view

When regenerating after edits, show this confirmation:
- “Regenerating will replace your current diagram edits. Do you want to continue?”

## Error Handling
- Empty input: Disable Generate Draft
- Unclear description: Request additional workflow detail
- Invalid AI response: Keep current diagram and show Retry
- Ambiguous branch: Render valid content and show warning
- AI service failure: Preserve current diagram and input
- Process exceeds limits: Ask user to shorten description

## Architecture
Use the following components:
- ProcessDiagramPage
- ProcessDiagramViewModel
- IWorkflowExtractionService
- WorkflowResponseValidator
- DiagramDraftBuilder

Responsibilities:
- IWorkflowExtractionService: Sends prompt, parses JSON response
- WorkflowResponseValidator: Validates workflow structure and graph integrity
- DiagramDraftBuilder: Converts workflow model into Syncfusion Diagram objects
- ProcessDiagramViewModel: Coordinates generation, acceptance, regeneration, and error handling

## Acceptance Criteria
- Flowchart is generated from a valid process description.
- Start, Process, Decision, and End nodes render correctly.
- Connectors and branch labels accurately represent workflow logic.
- Generated diagrams are editable.
- Warnings are shown for ambiguities.
- Invalid AI responses do not alter the current diagram.
- Regeneration after edits requires confirmation.
- User explicitly accepts the draft.
- No workflow is automatically executed or published.
- Solution remains a single-screen AI showcase.
